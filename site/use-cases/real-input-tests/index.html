Use case · End-to-end tests

Some widgets only work with real input. Test them with it.

Search-as-you-type, signature pads, drag-and-drop boards and per-keystroke validation wait for the events a person makes. Playwright's quickest calls skip those events, so the test fails on a widget that works, or you write a workaround for each one.

Where plain Playwright falls short

fill() sends no key events

Every key, pressed

human.type() presses and releases a key for each character, with Shift for capitals, so keyup handlers, input masks and per-keystroke validation all run.

Drags arrive in one jump

Moves the whole way

mouse.move() and dragTo() send a single move by default. human.drag() holds the button along a curved path, so signature pads and drag libraries get the stream of moves they wait for.

Scrolling skips the wheel

The wheel turns

Playwright scrolls a target into view without a single wheel event. human turns the wheel in bursts, so wheel handlers see a scroll, step by step.

Only need keys pressed? Playwright's pressSequentially() does that, at one fixed delay. Reach for human when you want one call per step that gets keys, paths and the wheel right.
