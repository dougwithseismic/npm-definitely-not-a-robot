Use case · Analytics and QA

Does your analytics record what visitors do? Check before they arrive.

Heatmaps, session replay, funnels and your own bot rules all read mouse, keyboard and scroll events. A plain Playwright script sends almost none of them, so it can't tell you whether they work. Seeded sessions that move like visitors can, and one that comes out wrong can be run again with its seed.

Where a plain script falls short

One pointer move per click

Trails, not dots

Each click travels a curved path made of dozens of pointer moves, so heatmaps and session replays have something to draw.

No keystrokes at all

Every key counted

page.fill() sends no key events, so keystroke counts and typing time come out as zero. human.type() presses each key, with a rhythm.

A bad session can't be repeated

Seeds replay a session

Give each session a seed. When one is recorded wrong, run that seed again and get the same paths and pauses while you fix it.

Run it on sites you own or are allowed to test. The library makes input look human; it doesn't hide automation, and it isn't for getting around anyone's bot protection. Responsible use.

The recipe

Run node synthetic-sessions.mjs. Each line is what one session sent: point it at your staging site and compare with what your analytics recorded.
